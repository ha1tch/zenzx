Hardware coverage vs. the Spectrum-family field

Every cell below is assessed against zenzx v0.4.26 as it actually stands, not as a wishlist. Green means the configuration works today and is tested. Yellow means it partly works — the underlying feature is real but a documented, tracked piece is still missing. Pink means the real machine has this and zenzx currently has nothing for it. Gray marked "Not applicable" means the real machine simply doesn't have this feature, so there is nothing to support — not a gap. Gray marked "Unconfirmed" (dashed border) is a genuinely different thing: research couldn't establish whether the real machine has this or not, so no judgement is made either way — not the same claim as "doesn't have it."

Notes

  1. zenzx's -joystick/-mouse flags accept an explicit override on any model regardless of what's built in, matching how real third-party interfaces plugged into any Spectrum's edge connector historically — Interface 2 (Sinclair protocol) and the Kempston interface were both usable on machines with no built-in port of their own, not just the ones that eventually got one built in.
  2. Memory contention isn't modeled for any machine in this table — filed as the general, non-machine-specific T-16. Not repeated as a pink cell throughout since it's a single project-wide gap, not a per-machine one.
  3. Unlike the Kempston-via-Twister case below, no source found this session specifically documents Sinclair-protocol (keyboard-remap) joysticks being commonly used on TS2068 via the Twister bus adapter — plausible by the same bus-bridging logic, but not established the way the Kempston case is, so marked as genuinely unconfirmed rather than either credited or ruled out.
  4. TS2068's built-in joystick ports use its own AY-register-14 mechanism, not Kempston or Sinclair protocol — implemented and tested this session (Stage 4). Confirmed this session that Kempston add-on interfaces were historically usable on TS2068 too, via a "Twister" bus adapter; zenzx's explicit -joystick kempston override works there as well.
  5. TS2068's real historical mouse support was AMX Mouse, not Kempston Mouse — confirmed directly from a genuine AMX Art tape disassembly this session (T-14), including the interrupt-driven X/Y mechanism and end-to-end register tracing. zenzx implements and tests this; the earlier version of this table incorrectly graded TS2068 against Kempston Mouse specifically (a protocol it never had) rather than against what it actually needed.
  6. Hi-colour mode itself works and is tested end-to-end (dynamic port-FFH switching, matching how real software actually engaged it). What's specifically incomplete is the documented Extension ROM CHNG_VID service call route, which hit an undiagnosed divergence and was set aside as T-15 once real software was confirmed not to depend on it.
  7. Chunk-0 Home/Extension ROM banking is implemented and verified (Stage 1). Full 8-chunk Dock/cartridge banking was explicitly out of scope from the original development plan, not an oversight.
  8. The CZ 2000 is architecturally a rebadged, unmodified Timex-Portugal 48K board — existing -model=48k may run its software with reasonable fidelity even without a dedicated model, but the specific machine (its exact ROM/board) isn't modeled.
  9. "Base cores match existing support" means zenzx's current 48K/128K/Pentagon-adjacent emulation covers what these platforms emulate as their standard modes — not that zenzx emulates the platform itself. The platform-specific enhancements (extra video modes, second AY, storage layer) are separately and genuinely unimplemented.
  10. The Omni ships on the Superfo Harlequin board — discrete 74HC logic, not FPGA. Functionally closest to the existing 128K/+3 configurations already modeled; the specific product and its integrated DivMMC storage aren't.
  11. ESPectrum (EremusOne's actively-maintained fork, 347 GitHub stars, 46 forks — genuinely significant open-source traction) is a software emulator on commodity ESP32 hardware, not a custom-silicon reimplementation — closer in kind to zenzx itself than to the FPGA platforms above. Confirmed directly from its own README: targets 48K, 128K, +2A (sharing the +3 ROM, matching the real hardware fact this table already establishes for the Amstrad line), Pentagon 128, and Microdigital TK90X/TK95.
  12. Several of these are genuine, confirmed gaps worth naming rather than folding into an already-tracked item: floating bus emulation, snow effect, Betadisk/TR-DOS, and the Fuller joystick protocol have no equivalent in zenzx at all currently. Memory contention specifically is the same gap already tracked as T-16 — ESPectrum implementing it is independent confirmation that it's a real, expected feature for a Spectrum emulator at this level of fidelity, not a nice-to-have.
  13. The Spectrum (Retro Games Ltd, £89.99, released 22 Nov 2024) is a closed-source, officially licensed consumer product — software emulation confirmed (not FPGA) by contemporary press coverage, though Retro Games Ltd has not published detailed technical documentation the way the open-source projects above have. In-device menu lets any connected USB controller be set to Kempston, Sinclair, or Cursor interface emulation, confirmed by Video Games Chronicle's review. Emulates 16K/48K/128K; no +3 or floppy support found in any source checked.
  14. Confirmed directly, not inferred: The Spectrum's own support FAQ (retro32.com) lists its internal ROM filenames verbatim — 48.rom, 128-0.rom, 128-1.rom for "128K Universal" mode, and plus3-1.rom/ plus3-2.rom/plus3-3.rom for a "+2A" mode. It runs genuine, unmodified Sinclair/Amstrad ROM images internally, not a from-scratch reimplementation — which settles AY directly (the 128K ROM requires it to boot) and confirms paging goes beyond generic 128K to the real +2A/+3-style extended scheme specifically, since that ROM set depends on it. A hands-on review separately confirms an explicit "128K/+2" mode selector in the device's own menu.
